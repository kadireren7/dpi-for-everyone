# Architecture (Linux packet mode)

This document is the technical design reference for `dpi-proxy-packet`,
the optional Linux packet-mode engine (NFQUEUE). The recommended
Linux engine is transparent mode — see
[docs/transparent-mode.md](transparent-mode.md). If you just want to run it,
see the main [README](../README.md) and [docs/packet-mode.md](packet-mode.md)
instead — this is for people modifying the code or auditing how it
works.

## High-level flow

1. On startup, the engine installs one nftables rule (see "nftables
   rule" below) that queues outbound TCP/80 and TCP/443 packets to a
   userspace NFQUEUE.
2. Each queued packet is parsed (IPv4/IPv6, then TCP) and, if it's the
   flow's first classifiable data, checked for an HTTP `Host` header
   or a TLS ClientHello SNI extension.
3. Once a flow is classified by domain, a strategy (`pass` or `split`,
   from `strategy.conf`) is looked up and cached on the flow for every
   subsequent packet.
4. `pass` accepts the packet unmodified. `split` (IPv4 TLS only, single
   -packet ClientHello only) constructs two replacement TCP segments,
   drops the original, and re-injects both via a raw socket.
5. On SIGINT/SIGTERM, the engine tears down the NFQUEUE binding and
   removes its nftables rule before exiting.

## nftables rule

Generated by `nft_rules_generate_create()` (`src/nfqueue/nft_rules.c`)
and applied via `nft -f -` (fork+execvp with a fixed argv — never
`system()`/`popen()` with an interpolated string, so there's no shell
to reinterpret anything):

```
table inet dpi_proxy {
	chain output {
		type filter hook output priority filter; policy accept;
		tcp dport { 80, 443 } meta mark != <NFT_ANTILOOP_MARK> counter queue num <N> bypass
	}
}
```

Notes:
- Single dedicated table (`inet dpi_proxy`); nothing else on the
  system's firewall is ever touched, and shutdown always attempts
  `nft delete table inet dpi_proxy` (idempotent — safe even if it
  doesn't exist).
- `bypass`: if no userspace program is bound to the queue (daemon
  crashed or isn't running), matched traffic falls back to normal
  `ACCEPT` instead of being silently dropped — fail-open, not
  fail-closed.
- `meta mark != <mark>` is the anti-loop exclusion — see below.

## Anti-loop mark

`NFT_ANTILOOP_MARK` (`include/nft_rules.h`) is a fixed `SO_MARK` value
set on the raw socket used to re-inject SPLIT segments
(`ensure_raw_v4_socket()` in `src/nfqueue/nfqueue_engine.c`). The
nftables rule explicitly excludes packets carrying that mark. Without
this, a re-injected split segment would immediately match the same
`tcp dport { 80, 443 }` rule and get re-queued — a packet storm on
every split connection. This is the single highest-risk mechanism in
the engine; it was verified by packet capture inspection showing no
duplicate/re-queued segments.

## Parsers and flow cache

- **IPv4/IPv6/TCP parsing** (`src/packet/ip.c`, `src/packet/tcp.c`):
  bounds-checked header parsing. IPv6 extension headers (hop-by-hop,
  routing, fragmentation, ...) are **not** walked — such packets are
  reported unsupported and fail open (ACCEPT, unclassified) rather
  than risk misparsing a header chain this project doesn't fully
  implement.
- **HTTP Host parsing** (`src/http/http.c`) and **TLS ClientHello/SNI
  parsing** (`src/tls/sni_extract.c`): read only the Host header /
  SNI extension bytes already visible in cleartext on the wire.
  Nothing about the TLS handshake itself (keys, certificates, session
  content) is touched or decrypted.
- **Flow table** (`src/flow/flow.c`): keyed by (family, src/dst
  addr+port), tracks in-order reassembly state per flow up to a
  bounded cap (`TLS_CLIENTHELLO_CAP`) so a malformed/oversized
  handshake can't grow memory without limit. Heap-allocated
  (`calloc`) in `nfqueue_engine_run()` rather than stack-local — the
  full table is large enough (~67MB) to reliably blow the default
  8MB thread stack if it were ever put there by mistake; this was
  caught by `test_flow.c` doing exactly that before the fix.
- **Strategy engine** (`src/strategy/strategy.c`): parses
  `strategy.conf`, exact-domain rules checked before suffix
  (`.`-prefixed) rules, last-write-wins on a repeated domain, and
  individually skips malformed lines with a `[strategy] line N: ...`
  warning rather than aborting the whole file.

## Strategy engine and chains

`t_strategy_chain` (`include/strategy.h`) is an ordered, fixed-size
(max 2) list of primitive actions — PASS/SPLIT/DISORDER/FAKE/FRAGMENT
— resolved per domain by `strategy_chain_for_domain()`
(`src/strategy/strategy.c`), same exact-then-suffix-then-default
precedence `strategy_for_domain()` always used. A config domain value
may be a single strategy name, or one of exactly three `+`-joined
chains (`fake+split`, `split+fake`, `split+disorder`) —
`strategy_chain_from_string()` validates every parsed chain against a
fixed safe-combination whitelist (`strategy_chain_is_safe()`) and
rejects anything else at config-parse time, same fail-safe posture as
an unrecognized single strategy name. `split+disorder` is normalized
to plain `disorder` at parse time: DISORDER's only correct
construction already *is* split-then-reorder, so that combination has
no distinct safe meaning. See
[docs/packet-mode.md](packet-mode.md#strategies) for what each action
actually does on the wire.

## Packet-construction primitives

Three files under `src/packet/` build the wire-valid packets every
chain action needs; all are pure, allocation-free functions (no I/O,
fully unit-testable) that only ever read `in`/write `out` buffers the
caller owns:

- **`split.c`** — `packet_split_tcp_v4()`/`_v6()`: re-segments a
  captured TCP payload into two independent, wire-valid TCP segments
  at a caller-chosen offset (seq/checksum/IP-length corrected on
  both). Used by both SPLIT and DISORDER (DISORDER just transmits the
  two results in reversed order — see below).
- **`fragment.c`** — `packet_fragment_ipv4()`: true IP-layer
  fragmentation (RFC 791) of an already-complete, already-checksummed
  datagram — deliberately a different mechanism from TCP segmentation.
  Splits at the next 8-byte-aligned IP-payload offset at or after the
  end of the TCP header; fragment 1 carries the full TCP header, but
  its TCP checksum is *never recomputed* — the original checksum
  already covers the complete payload, and IP reassembly at the
  destination reconstructs those exact bytes before TCP ever sees it.
  Both fragments share the original IP ID; `IP_FLAG_DF` is cleared on
  both if it was set on the input (fragmenting a DF datagram at all
  only happens because this function was explicitly asked to).
- **`fake.c`** — `packet_make_fake_tcp_v4()`: builds one decoy segment
  from any valid captured/constructed IPv4/TCP packet — same 5-tuple/
  seq/ack/flags, IP TTL set to the caller's `fake_ttl`, IP header
  checksum kept **valid** (so ordinary forwarding still carries it
  toward wherever a DPI box might be inspecting), TCP checksum
  deliberately flipped to its bitwise complement (always different —
  `checksum == ~checksum` has no 16-bit solution — so it's reliably
  invalid, which is what makes a real endpoint's TCP stack/NIC RX
  checksum offload drop it before application/stream state is ever
  touched). Belt-and-suspenders with the lowered TTL; neither is a
  network-topology guarantee, both are documented as heuristics.

## Chain execution and injection

`try_apply_chain()` (`src/nfqueue/nfqueue_engine.c`, which generalizes the
SPLIT-only `try_apply_split()`) dispatches on the resolved
chain's shape and calls the primitives above. The invariant
`try_apply_split()` established is preserved and generalized: **every
packet a chain step needs is built in memory before the original is
ever `NF_DROP`'d.** If a *required* piece fails to build (e.g. no
usable SNI split offset, or `packet_split_tcp_v4()` itself fails), the
function returns before dropping anything and the caller's default
`ACCEPT` runs on the untouched original. If a *best-effort* piece
fails — specifically, a FAKE decoy layered onto a SPLIT chain — it's
logged at `warn` and skipped, and the chain degrades to the plain
action it was layered onto (still safe, still built-then-dropped)
rather than aborting entirely. Plain `fake` (the one action that never
touches the real packet at all) never drops or rebuilds anything —
it only injects the decoy and lets the caller's default `ACCEPT`
carry the real, completely unmodified packet through.

Injection is the same raw `IPPROTO_RAW`/`IP_HDRINCL` socket (`inject_ipv4_packet()`), `SO_MARK`-tagged with
`NFT_ANTILOOP_MARK` for every packet this engine ever sends, decoys
included. A failed injection after the drop is logged as a real error
(`raw_send_failures` in the stats line), not silently swallowed.

**What's been verified for DISORDER/FAKE/FRAGMENT/chains**: unit tests
plus ASan+UBSan on synthetic-but-structurally-correct packets
(`tests/unit/test_fragment.c`, `tests/unit/test_fake.c`, chain-parsing
coverage in `tests/unit/test_strategy.c`), the same standard the
SPLIT code was held to *before* its own live-traffic validation. No
live NFQUEUE run of DISORDER/FAKE/FRAGMENT/the chains has been done
yet.

## Checksums

`checksum_ipv4_header()`/`checksum_tcp_v4()` (`src/packet/checksum.c`)
compute real checksums in userspace before `sendto()` on the raw
socket — the kernel doesn't get a chance to override them the way it
would for a normal socket with checksum offload. One thing not to
misdiagnose: if a packet capture tool flags a checksum as "bad" on
packets your *kernel* generated normally (e.g. the client's own SYN),
that's very likely TX checksum offload (modern NICs compute the real
checksum in hardware, so the kernel leaves a placeholder in the copy a
capture tool sees) — normal, not a bug. This should **not** apply to
the engine's own split segments, since those bypass offload entirely;
a bad checksum on those specifically would be a real bug.

## Fail-open behavior, summarized

- nftables rule uses `bypass` (daemon down → normal ACCEPT).
- Unsupported/malformed/fragmented (in the *arriving* IP-fragment
  sense — see `packet_parse_ipv4()`) packets, IPv6 chain attempts (not
  wired to the wire — always PASS), and any failed chain-construction
  step all fall back to ACCEPT.
- A malformed `strategy.conf` line — including an unsafe/unsupported
  chain combination — is skipped individually, never treated as fatal.
- A chain's original packet is never dropped until every *required*
  replacement packet exists in memory, fully built; a best-effort
  piece (a FAKE decoy) failing degrades the chain instead of aborting
  it. See "Chain execution and injection" above.

## Privilege model (system service)

See [systemd/dpi-proxy-packet.service](../systemd/dpi-proxy-packet.service)
and [docs/packet-mode.md](packet-mode.md) for how this is wired up as
a system service: the engine needs exactly `CAP_NET_ADMIN` (nftables
rule management, NFQUEUE bind) and `CAP_NET_RAW` (the raw injection
socket) — verified running under a systemd unit whose
`CapabilityBoundingSet` contains only those two capabilities, rather
than unrestricted root.
